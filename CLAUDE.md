# hscfdoral.com: build guide

Website for **Healthy Solutions for Children and Families (HSCF)**, a bilingual (Spanish/English) mental health center at 8245 NW 36th St, Ste 7, Doral, FL 33166 · (305) 594-5658 · (786) 423-9495 · info@hscfdoral.com.

It is a static site generated by Python. **Spanish is the main language** and lives at the site root on the same addresses the old WordPress site used; English mirrors every page under `/en/`. A team of Claude agents writes a new researched blog post on the 1st and 15th of every month and publishes it automatically. Read this file before changing anything.

---

> **First time on a new computer:** if `.claude/agents/` or `.claude/skills/` is missing, run `bash claude-agents/install.sh`. It copies the agents and slash commands from `claude-agents/` into `.claude/`. Edit them in `claude-agents/` and re-run the installer, so the two stay identical.

## Golden rules

1. **`site/` is generated.** Never hand-edit HTML, `sitemap.xml`, `robots.txt`, `ai.txt`, `llms*.txt`, `feed.xml` or `.htaccess` in `site/`. Change `build/`, `content/` or `seo/config.json`, then run `python3 build/build.py`. Only `site/assets/` is hand-made.
2. **Every page exists twice**, Spanish and English, linked to each other with hreflang. Never add one language without the other.
3. **Keep the old addresses.** Spanish pages and old blog posts keep their WordPress URLs. If you must move a page, add a 301 to `REDIRECTS` in `build/build.py`.
4. **Health content follows the gates.** Posts are published automatically only when every gate in `build/articles.py` → `publish_gate()` passes (5+ opened-and-verified sources, 2+ peer-reviewed/systematic-review/guideline sources, risk not high). High-risk topics are held for a clinician (`/publish-article`). Never invent a reviewer, credential, statistic, citation, testimonial or review.
5. **Describe the staff honestly.** Several team members are interns, students, coaches or behavior analysts. Never call anyone "licensed", or the team "psychologists", unless it is true and confirmed.
6. **Run the audit before every push:** `python3 build/audit.py` must report 0 errors.
7. **Never store server or GitHub credentials in this project.** SSH DELUXE holds the server connection; the server reads GitHub with a read-only deploy key.
8. **Keep it fully mobile.** Nothing may scroll sideways at any width from 320 px to 2560 px.

## Commands

| Task | Command |
|---|---|
| Build the live site into `site/` | `python3 build/build.py` |
| Validate content and posts only | `python3 build/build.py --check` |
| Build with drafts into `preview/` (never publish this) | `python3 build/build.py --drafts` |
| Technical SEO audit of `site/` | `python3 build/audit.py` |
| Audit the live site | `python3 build/audit.py --live` |
| Re-import the old site's photos | `python3 build/tools/import_old_media.py ~/Desktop/hscfdoral-media` |
| Pull GA4 + Search Console data | `python3 seo/scripts/fetch_google_data.py` |
| Preview locally | `cd site && python3 -m http.server 8000`, open http://localhost:8000 |

Python 3.9+ and the standard library build the site (Pillow is needed only to re-import photos). `pip install -r seo/scripts/requirements.txt` adds full JSON Schema validation and the Google data pull.

### Claude commands (in Claude Code, from this folder)

| Command | What it does |
|---|---|
| `/auto-post` | The automatic post (what the scheduled task runs on the 1st and 15th): next topic from the plan → research → publish if the gates pass, else draft → build → audit → push |
| `/new-article <topic>` | Research and write a post saved for review. `/new-article auto <topic>` publishes it if the gates pass |
| `/publish-article <id>` | Publish a held draft after a person reviews it (required for high-risk topics) |
| `/seo-review` | 6-month review: pulls GA4/Search Console, grades the plan, writes the next one and its content calendar |
| `/site-audit [live]` | Schema, crawlability, AI files, hreflang, links, mobile |
| `/deploy` | First time: server setup through **SSH DELUXE**. Afterwards: build, audit, push to GitHub |

Agents: `psych-research-writer` (research + writing, review or automatic mode), `seo-strategist`, `technical-seo-auditor`.

## How publishing works

```
1st & 15th  scheduled Claude task ──▶ /auto-post ──▶ commit + push ──▶ GitHub paco3463/hscfdoral (private)
                                                                           │
web server: cron every 15 min ── git pull (read-only deploy key) ── copy site/ → web root
```

Any push to `main` goes live within 15 minutes. Server setup: `deploy/SERVER-SETUP.md`; the pull script: `deploy/server-pull.sh`. Settings: `seo/config.json` → `auto_blog` (set `enabled` to false to pause automatic posts).

## Changing page copy

- All copy lives in `build/content_es.py` and `build/content_en.py`. Change both. Keys, list lengths and ids must match.
- Strings may contain simple inline HTML (`<strong>`, `<em>`, `<br>`, `<a>`). Straight quotes become typographic automatically.
- Page `title`: **60 characters or fewer**, ending `| HSCF`. `description`: **110 to 158 characters**. The audit checks both.
- A new service needs an entry in both files with its own `slug` per language. A staff member's `old` list holds previous WordPress slugs; they 301 automatically.
- All content comes from the old site or the practice. Don't add hours, prices, credentials or claims the practice hasn't confirmed.

## Blog posts

Each post is a folder `content/articles/<id>/` with `meta.json` (validated by `schemas/article.schema.json`), `es.md` and `en.md`.

- **`kind`**: `article` (researched, numbered sources) or `legacy` (migrated from the old blog at its original `legacy_url`).
- **`review_policy`**: `automatic` (published once the gates pass), `clinician` (needs `medical_reviewer`), or `legacy`.
- **`risk`**: `high` for suicide, self-harm, abuse, eating disorders, substance-use treatment, medication, psychosis or crisis. High-risk posts are never published automatically.
- **`status`**: `draft` → `in_review` → `published` → `archived`. Only `published` posts are built into `site/`; `--drafts` builds everything into `preview/` with a banner and `noindex`.
- The address comes from `date_published`: `/<yyyy>/<mm>/<es.slug>/`.
- Every article shows a note saying how it was made (clinician-reviewed, or researched and written with AI tools by the editorial team); legacy posts show their original date. Never imply a review that didn't happen.
- `hero_image` reuses a local photo (see `build/media.json`); never hotlink.

### Markdown the build understands

```
Opening paragraph with no heading. Citations go after claims [1] or [2, 4].

## Section heading        (no "# "; the title comes from meta.json)
### Subheading

- bullet item            (orange house marker)
1. numbered item

> A tip callout box.

**bold**, *italic*, [external link](https://...)
[ABA](service:aba)                         → the service page in the right language
[escríbenos](page:contact)                 → pages: home, about, activities, news, events, gallery, services, insurance, staff, blog, contact, areas
[otro artículo](article:<id>)              → another published post
```

The build adds breadcrumbs, author and date, reading time, a table of contents (3+ sections), the crisis box (988/911), the "how this was made" note, numbered sources with DOIs, FAQs, related services, related posts and the call-to-action band.

## Design system

Tokens are at the top of `site/assets/css/styles.css`. **Every color comes from a token**; no hex or `rgba()` literals in rules and no inline `style=""` in templates.

| Token | Value | Use |
|---|---|---|
| `--ember` | `#FE4109` | Logo orange: shapes, icons, house markers, large decorative type. Never small text. |
| `--ember-ink` | `#C93203` | Same orange deepened for WCAG AA: buttons, links, badges, the CTA band. |
| `--apricot` | `#FA8D4A` | Logo light orange: accents on dark backgrounds, dots. |
| `--apricot-soft` | `#FDC9A6` | Image placeholders |
| `--blush` | `#FFEDE2` | Tinted section bands |
| `--milk` | `#FFFBF7` | Page background |
| `--white` | `#FFFFFF` | Cards and panels |
| `--cocoa` | `#3A2219` | Text, footer, dark bands |
| `--cocoa-2` / `--dune` | `#57372B` / `#7D6156` | Secondary text |

**Type:** Fraunces (display) and Figtree (body), self-hosted. **Motif:** the logo's house (house-shaped photos, house bullets, roofline under the hero, splash through the logo, the breathing house). **Breakpoints:** 480 (full-width buttons), 760 (hero stacks), 980 (one column), 1200 (desktop menu), 1200–1379 (compact menu). **Mobile check** after template or CSS changes: no sideways scroll at 320, 360, 390, 414, 768, 1024, 1200, 1280, 1440, 1920, 2560 in both languages.

## Interactive features (`site/assets/js/main.js`)

Splash (home, once per session, `?nosplash` skips), hero video (`assets/media/`), finder (`FINDER` in the content files), breathing minute, workshop popup (`EVENT`, removes itself after `data-end`), staff and blog filters, YouTube videos that load only on click (youtube-nocookie), gallery lightbox, contact form (Formspree `YOUR_FORM_ID`, falls back to the visitor's email app), and privacy-safe analytics events.

## Crawling and AI files

Generated from `seo/config.json` and the content: `sitemap.xml` (hreflang es/en, x-default = Spanish), `robots.txt` (AI search and training bots per `ai_crawlers`), `ai.txt`, `llms.txt` and `llms-full.txt`, RSS feeds, and `.htaccess` (404, MIME types, compression, caching, security headers, the old-URL 301s, WordPress paths return 410; HTTPS redirect commented out until SSL is confirmed).

## Analytics and privacy

The GA4 tag appears only when `seo/config.json` → `google.ga4_measurement_id` is set (signals and ad personalization off). Events: `generate_lead`, `click_to_call`, `click_email`, `book_consultation_click`, `workshop_rsvp`, `language_switch`, `finder_select`. **Never send names, contact details, message text or anything about a person's health.** The contact form asks people not to include health details.
